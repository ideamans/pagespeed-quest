# AI / docs artifact policy

PageSpeed Quest serves one body of knowledge to four audiences: the `psq llm`
subcommand, context7, the Claude Code plugin under `plugins/pagespeed-quest/`,
and `gh skill`. They all read from the same source, and only one file in the
chain is generated.

## Never hand-edit this file

- `llmdocs/90-commands.md` — generated by `scripts/build-llm-docs.js` from the
  actual command tree in `src/cli.ts`. `yarn test` fails if it is stale
  (`test:llmdocs` runs the generator with `--check`).

## If you want to change what agents see, edit the source

| Want to change… | Edit this |
| --- | --- |
| the rules and failure modes agents get wrong | `llmdocs/00-guide.md` |
| the inventory schema and file layout | `llmdocs/10-inventory.md` |
| which edit models which optimization | `llmdocs/20-experiments.md` |
| how to measure, compare, film | `llmdocs/30-measuring.md` |
| the command catalog | `src/cli.ts`, then regenerate |
| CLI flags, defaults, descriptions | `src/cli.ts` (help text is what the catalog prints) |
| inventory read/write behaviour | `src/inventory.ts`, `src/http.ts`, `src/formatting.ts` |
| what Lighthouse / loadshow / webshot are told | `src/lighthouse.ts`, `src/loadshow.ts`, `src/webshot.ts` |
| the `summary.md` digest | `src/lighthouse-summary.ts` |
| context7 rules | `context7.json` (`rules` — pitfalls only, not what the code already says) |
| skill bodies | `plugins/pagespeed-quest/skills/*/SKILL.md` |
| plugin manifest version | `plugins/pagespeed-quest/.claude-plugin/plugin.json` — must equal `package.json.version` |

After any of those, run `/regen-ai` (or `yarn ai:regen`).

## Non-negotiables for the distributed skills

Checked by `scripts/validate-plugin-skills.js`, which runs inside `yarn test`:

- exactly five frontmatter fields — `name`, `description`, `license`,
  `compatibility`, `allowed-tools`. No Claude-specific keys: the same files are
  read by `gh skill`, Copilot, Cursor and Gemini CLI
- `name` matches the directory
- every skill ends with a `## Failure modes` table
- the bundle ships an install skill and a usage skill
- `plugin.json.version` equals `package.json.version`

`llmdocs/` and the skills are written in **English** — this project's users are
global, and the skills are how other agents discover the tool.

## Why

The failure mode this prevents is silent: nobody notices when the LLM knowledge
goes stale. A wrong `--help` gets reported by a human within a day; a wrong
`llmdocs/00-guide.md` just makes agents quietly do the wrong thing, and the
symptom is "somehow it doesn't work well".
